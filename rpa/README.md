# 添付ファイルの共有フォルダ転送（RPA 連携）

申請審査完了となった申請の添付ファイルを、社内ファイルサーバの共有フォルダへ複製する。

**このフォルダは ServiceNow アプリの一部ではない。** `now-sdk build` / `now-sdk install` の対象外であり、
RPA を実行するマシンへ配置して使う。

## 構成

| ファイル | 役割 |
| --- | --- |
| `Export-SksAttachments.ps1` | 処理本体。REST API で添付を取得し、共有フォルダへ配置する |
| `Set-SksExportCredential.ps1` | ServiceNow 接続用の資格情報を暗号化して保存する（初回のみ） |
| `config/export-config.sample.json` | 設定ファイルのひな形 |
| `test/Invoke-ExportTests.ps1` | 自動テスト。13シナリオ・46項目を検証する |
| `test/Mock-ServiceNow.ps1` | 検証用のモックサーバ（ServiceNow REST API を模倣） |

RPA ツール（UiPath / Power Automate Desktop / WinActor 等）からは
`Export-SksAttachments.ps1` を1行で呼び出し、終了コードで分岐する。

ファイル取得とファイル I/O を RPA のアクティビティで組み立てていないのは意図的である。
ワークフロー形式が製品間で互換でないため、中核を PowerShell に置くことで
RPA 製品の乗り換え時に作り直しが発生しないようにしている。

## なぜ ServiceNow の画面を操作しないのか

添付の取得は Attachment REST API で行う。ブラウザ操作でのダウンロードは
UI のバージョンアップやテーマ変更で壊れるため採用していない。
RPA の担当は「呼び出しとスケジューリング、結果の通知」に限定する。

## セットアップ

### 1. ServiceNow 側に連携用アカウントを作成する

専用の連携用アカウントを用意し、必要最小限のロールのみ付与する
（トンマナ 2.1.1 最小権限の原則）。

必要な権限は次の2つのみ。

- 対象テーブル（`x_dent2_dentsusoke_request`）の read
- `sys_attachment` の read

`writeBackField` を使う場合のみ、対象テーブルの write を追加する。
admin や事務局ロール（`x_dent2_dentsusoke.staff` 等）を付与してはならない。

### 2. 設定ファイルを作成する

```powershell
Copy-Item .\config\export-config.sample.json .\config\export-config.json
notepad .\config\export-config.json
```

| キー | 説明 |
| --- | --- |
| `instanceUrl` | ServiceNow のインスタンス URL |
| `credentialPath` | 暗号化された資格情報ファイルの保存先 |
| `shareRoot` | 共有フォルダのルート。配下に申請番号のフォルダを作成する |
| `stagingDir` | ダウンロードの一時領域。処理後に必ず削除される |
| `ledgerPath` | 転送台帳の保存先（後述） |
| `logDir` | 監査ログの保存先 |
| `targetStatus` | 転送対象の申請ステータス。既定は `review_done`（申請審査完了） |
| `additionalQuery` | 追加の絞込条件（エンコード済みクエリ）。ServiceNow 側に転送状態の項目を追加した場合に使う |
| `maxApplications` | 1回の実行で処理する申請の上限。上限に達した場合は警告を出す |
| `maxAttachmentBytes` | 添付1件のサイズ上限。既定は 50MB |
| `allowedExtensions` | 許可する拡張子。実行可能形式が共有フォルダへ入るのを防ぐ |
| `writeBackField` | 転送済みを ServiceNow へ書き戻す項目名。空なら書き戻さない |
| `logRetentionDays` | ログの保存日数。監査要件に合わせて設定する |

### 3. 資格情報を保存する

**RPA を実行するサービスアカウントで、RPA を実行するマシン上で**実行する。

```powershell
.\Set-SksExportCredential.ps1 -ConfigPath .\config\export-config.json
```

パスワードは Windows の DPAPI で暗号化される。暗号化したユーザ・マシン以外では復号できないため、
管理者の個人アカウントで作成したファイルはサービスアカウントから読めない。

### 4. 接続確認

```powershell
.\Export-SksAttachments.ps1 -ConfigPath .\config\export-config.json -DryRun -Verbose
```

`-DryRun` はダウンロードと配置を行わず、対象件数のみを出力する。

## RPA からの呼び出し

```
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\SKS\rpa\Export-SksAttachments.ps1" -ConfigPath "C:\SKS\rpa\config\export-config.json"
```

標準出力の最終行に結果が1行で出るので、RPA 側でそのまま通知本文に使える。

```
対象申請=3 / 添付=4 / 転送=3 / 対象外=0 / 要確認=1 / 失敗=0
```

### 終了コードでの分岐

| コード | 意味 | RPA 側の扱い |
| --- | --- | --- |
| 0 | 全件成功（対象0件を含む） | 正常終了。通知不要 |
| 1 | 一時的な失敗あり | 次回実行で回復する可能性がある。連続した場合のみ通知 |
| 2 | 致命的エラー | 再実行しても回復しない。即時に運用担当へ通知 |
| 3 | ポリシー違反の添付を検出 | 事務局へ通知し、添付の内容を確認してもらう |

2 は設定不備・認証失敗・共有フォルダ到達不可などで、1件も処理していない状態である。
3 は拡張子の許可リスト外、またはサイズ上限超過の添付を検出した場合で、
検出した実行でのみ返る（台帳へ記録するため翌回は繰り返さない）。

1 と 3 が同時に発生した場合は、緊急度の高い 1 を返す。

## 転送台帳について

ServiceNow 側の添付は削除しないため、本処理は「移動」ではなく「複製」である。
したがって転送済みかどうかを台帳（`ledgerPath` の JSON）で判断しないと、
再実行のたびに二重転送する。

台帳は `sys_attachment` の sys_id をキーにしている。添付は更新されず、
差し替え時は別レコードになるため、sys_id が一致すれば同一の実体である。

**台帳は必ずバックアップ対象に含めること。** 失われると全件が未転送と判定され、
大量の二重転送が発生する（ファイル名の衝突は連番退避されるため上書きはされないが、
共有フォルダに同じ内容の重複ファイルが並ぶ）。

台帳が大きくなってきた場合は、`-Since` で取得対象を日時で絞るか、
ServiceNow 側に転送状態の項目を追加して `additionalQuery` で絞り込む。

```powershell
.\Export-SksAttachments.ps1 -ConfigPath .\config\export-config.json -Since '2026-09-01'
```

## 配置されるファイル

```
\\fileserver\sks\applications\
  APP-2026-00123\
    決算書_2025年度.pdf
    見積書.pdf
  APP-2026-00124\
    ...
```

ファイル名は Windows で使用できない文字（`< > : " / \ | ? *`）と制御文字を `_` に置換し、
末尾の空白・ピリオドを除去する。予約デバイス名（`CON` `PRN` `NUL` 等）には `_` を前置する。
日本語のファイル名はそのまま保持する。

同名ファイルが既にある場合は `ファイル名(2).pdf` のように連番を付けて退避し、**上書きしない**。
事業者が同じファイル名で再提出した場合に原本が失われるのを防ぐためである。

## 安全性に関する実装上の配慮

対象の添付は決算書・登記簿・見積書等の機微情報を含むため、次の処理を入れている。

- **ステージングの確実な削除** — ダウンロードした一時ファイルは成功・失敗にかかわらず削除する
- **ハッシュ検証** — ダウンロード後と共有フォルダ配置後に SHA-256 を比較し、転送中の破損を検出する
- **サイズ検証** — `sys_attachment.size_bytes` と実際のサイズを比較する
- **一時名での配置** — `.part` で書いてから改名するため、転送中のファイルを後続処理が拾わない
- **台帳の更新順序** — 配置完了後に記録する。逆順にすると配置失敗した添付が転送済みとなり恒久的な転送漏れになる
- **台帳の原子的な書き込み** — 一時ファイルへ書いてから置き換えるため、異常終了で台帳が壊れない
- **ログの内容** — 申請番号・ファイル名・ハッシュは記録するが、ファイルの内容と資格情報は記録しない
- **リトライ** — 通信エラーと 429／5xx は指数バックオフで3回まで再試行する。401／403／404 は再試行しない

共有フォルダ側のアクセス権は、サービスアカウントの書き込み権限と、
事務局の閲覧権限のみに絞ることを推奨する。

## 注意事項（ServiceNow 側の未実装）

現時点では本スクリプトを実運用で動かすことはできない。
次の2点が ServiceNow 側に存在しないためである。

1. **添付ファイルの実装がない** — `sys_attachment` を扱うコードがアプリ内に存在しない。
   申請の添付書類は申請機能（ITCOM 主担当）の範囲であり、
   どのタイミングでどの書類が添付されるかが未確定である。

2. **`review_done` へ遷移する処理がない** — 一次審査・信用調査・採択判定は本スライスの範囲外。
   転送の契機となるステータス遷移が発生しない。

また `sys_attachment` の ACL がアプリ側に定義されていない
（`src/fluent/acls/portal-acls.now.ts` に添付の定義なし）。
事業者が自社の申請に紐づく添付のみを扱えるよう制限する ACL を先に整備すべきである。

## 検証

### 第1段階：自動テスト（モックサーバ）

```powershell
.\test\Invoke-ExportTests.ps1
```

ServiceNow は不要。`test\Mock-ServiceNow.ps1` が localhost で ServiceNow REST API を模倣し、
13シナリオ・46項目を検証する。所要時間は1分程度。終了コードは 0（全件成功）／1（失敗あり）。

実インスタンスではこの検証ができない。申請の添付と申請審査完了への遷移が未実装であるうえ
（いずれも申請機能＝ITCOM 主担当の範囲）、サイズ不一致・5xx・401 といった異常系は
実インスタンスでは意図的に起こせないためである。

| ID | シナリオ | 主な検証内容 |
| --- | --- | --- |
| T01 | 設定ファイル不在 | 終了コード2 |
| T02 | 資格情報ファイル不在 | 終了コード2、セットアップ手順の案内 |
| T03 | 共有フォルダ到達不可 | 終了コード2、API 呼び出し前に落ちること |
| T04 | 認証失敗（401） | 終了コード2、**再試行しないこと**、ロール確認の案内 |
| T05 | 対象0件 | 終了コード0（0件は異常ではない） |
| T06 | DryRun | 配置0件、台帳を作成しないこと |
| T07 | 正常系 | 3件配置、日本語名の保持、予約デバイス名・不正文字のサニタイズ、ハッシュ記録、ステージング残留なし、申請番号未採番のスキップ |
| T08 | 再実行 | **冪等性**（転送0件／対象外3件、ファイル数が増えない） |
| T09 | 台帳喪失後の再実行 | 上書きせず連番で退避すること |
| T10 | ポリシー違反 | 終了コード3、`.exe` とサイズ上限超過を配置しないこと、台帳へ `rejected` と理由を記録 |
| T11 | ポリシー違反の再実行 | 終了コード0に戻ること（**同じ添付でアラームを繰り返さない**） |
| T12 | サイズ不一致 | 終了コード1、共有フォルダへ置かない、台帳へ記録しない、ステージングに機微情報を残さない |
| T13 | 一時的な障害（503×2） | リトライで回復して終了コード0、再試行のログ |

テスト結果とログは作業ディレクトリ（既定 `%TEMP%\sks-rpa-test\<日時>`）に残る。
失敗時はそこのログと共有フォルダの状態を確認する。実行ごとに別ディレクトリを作るため、
過去の結果は上書きされない（不要になったら手動で削除する）。

ポートが使用中で失敗する場合は `-BasePort` を変える。

```powershell
.\test\Invoke-ExportTests.ps1 -WorkRoot D:\Temp\sks -BasePort 18200
```

### 第2段階：検証インスタンスとの疎通確認

自動テストが通ったら、実際の ServiceNow で疎通と権限を確認する。
添付が未実装のため、**検証用の添付を手で付けて代替する**。

1. 連携用アカウントを作成し、対象テーブルと `sys_attachment` の read のみ付与する
2. `Set-SksExportCredential.ps1` で資格情報を保存する
3. 検証用の申請レコードを1件作り、`u_application_status` を `review_done` にする
4. そのレコードへ PDF を数件添付する（プラットフォーム UI の添付ボタンから）
5. `-DryRun` で対象件数が合うことを確認する
6. `-DryRun` を外して共有フォルダへ配置されることを確認する
7. もう一度実行し、転送0件・対象外N件になることを確認する

ここで確認したいのは自動テストで代替できない次の3点である。

- 連携用アカウントのロールが不足していないか（不足すると終了コード2）
- 共有フォルダへサービスアカウントが書き込めるか（UNC パスと NTFS 権限）
- 日本語ファイル名がファイルサーバ上で正しく保持されるか

### 第3段階：RPA からの実行確認

RPA ツールから呼び出し、終了コードで分岐できることを確認する。
終了コードは意図的に発生させられる。

| 確認したい分岐 | 発生させ方 |
| --- | --- |
| 2（致命的） | 設定ファイルの `shareRoot` を存在しないパスに変える |
| 3（要確認） | 申請へ `.exe` などの許可外拡張子のファイルを添付する |
| 1（一時的な失敗） | 実行中に共有フォルダのネットワークを切断する |

サービスアカウントで動かすことも必ず確認する。DPAPI はユーザ・マシンに紐づくため、
開発者の個人アカウントで作成した資格情報ファイルはサービスアカウントから復号できない。
RPA から実行したときだけ終了コード2になる場合は、まずここを疑う。

## 実行環境

Windows PowerShell 5.1 で動作する記法のみを使用している。PowerShell 7 固有の構文は使っていない。

`.ps1` は**BOM 付き UTF-8** で保存する必要がある。BOM がないと Windows PowerShell 5.1 が
システム ANSI として読み、日本語のコメントと文字列が壊れて構文エラーになる。
編集後は次のコマンドで構文を確認できる。

```powershell
$errors = $null
[System.Management.Automation.Language.Parser]::ParseFile((Resolve-Path .\Export-SksAttachments.ps1).Path, [ref]$null, [ref]$errors)
$errors
```
